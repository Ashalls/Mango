## 0. Priority: the vanishing document grid ("tray grid disappears until right-click")

> **✅ ADDRESSED (2026-07-12).** Fixed on three fronts: (1) `MainPanel.tsx` now keeps
> `DocumentTable` at one stable tree position (the split/non-split layouts were separate JSX
> branches, so ag-grid was unmounted+remounted on every row click — the prime moment it latched a
> 0-height viewport); (2) the self-heal is now **state-based** — on any resize it repaints when the
> wrapper is sized but ag-grid has rendered zero row nodes (`api.getRenderedNodes().length === 0`),
> plus an `onGridSizeChanged` companion — dropping the fragile `prevHeight === 0` gate the coalesced
> ResizeObserver defeated; (3) `getRowId` no longer uses the nonexistent `params.rowIndex` and now
> gives `_id`-less / object-`_id` rows stable ids (a separate blank mode right-click did NOT fix).
> Also moved the add-row `useState` hooks above the early return (Rules-of-Hooks fix). Still
> recommended as follow-up: memoize `columnDefs`/`rowData` and fix the no-selector store
> subscriptions (perf; removes the re-render storm) — deferred to avoid the closure-staleness risk.

Root cause is **not** primarily the height-collapse the previous two fixes chased. Two things combine:

1. **Right-click heals it because *any* re-render heals it.** `columnDefs` is rebuilt as a fresh
   array on every render (`DocumentTable.tsx:244`, unmemoized). Right-click → `onCellContextMenu`
   → `setContextDoc` → re-render → new column-defs identity → ag-grid re-lays-out and repaints.
2. **ag-grid latches a transient 0-height viewport the self-heal misses.** The canary at
   `DocumentTable.tsx:212` gates on `prevHeight === 0`, but ResizeObserver coalesces a
   collapse→restore within one frame into a single *positive* entry, so the 0 is never witnessed
   and the `[DocumentTable] grid wrapper collapsed` warning never fires.

Confirmed triggers:
- DocumentTable is **fully remounted on every row click** — the two `MainPanel.tsx:170-196`
  ternary branches have mismatched element types at child slot 0.
- The split pane at `MainPanel.tsx:178` reintroduces the `%`-height-of-a-flex-grown-item Chromium
  bug the comments warn about (moved up one level, not removed).
- No-selector `useTabStore()` at `DocumentTable.tsx:155` → re-render storm (per Claude streaming
  token, per drag pointermove) that randomly masks/heals the bug.

Separate blank-grid mode right-click does **not** fix: `getRowId` at `DocumentTable.tsx:553` uses
`params.rowIndex` (does not exist on `GetRowIdParams`); `_id`-less results get id `"undefined"`
for every row and object `_id`s get `"[object Object]"`, so ag-grid merges/drops duplicate-id rows.

**Durable fix, in order:**
1. `useMemo` `columnDefs` + `rowData` (deps: documents, isReadOnly, tab.isView, addRowOpen,
   addRowValues) — removes the accidental heal and the column churn.
2. Keep DocumentTable at one stable tree position: render the split container unconditionally,
   vary only pane style. Replace the `%`-height pane with a measured pixel height / flex-basis.
3. State-based self-heal (drop the `prevHeight===0` gate): on any RO tick and in
   `onGridSizeChanged`, if `height>0 && api.getDisplayedRowCount()===0 && docCount>0` →
   `resetRowHeights(); redrawRows()`.
4. Fix `getRowId`: guard null, `JSON.stringify` object `_id`s, counter fallback for `_id`-less docs.

## 1. Critical

- **C1. ✅ RESOLVED (2026-07-12).** _Queries & writes hit the globally "active" connection, not the
  tab's._ Fixed by threading each tab's `connectionId` through every `trpc.query.*`/`trpc.mutation.*`
  input into `getDb(name, connectionId)`, across the query/mutation routers, actions, and all
  renderer callers (find, count, documentSource, aggregate/stage-preview, explain, insert/update/
  delete one+many, and the bulk dialogs). `checkReadOnly(connectionId?)` now guards the same
  connection the write targets. Follow-up not covered here: the `exportImport` router still uses the
  active connection for the actual export stream (read-only, no data-loss risk).
- **C2. ✅ RESOLVED (2026-07-12).** _Aggregation `$out`/`$merge` bypassed every write guard._ The
  aggregate actions now reject a pipeline containing `$out`/`$merge` when the target connection is
  read-only (`pipelineHasWriteStage` + `checkReadOnly` in `actions/query.ts`, covering both the
  tRPC `query.aggregate`/`aggregateWithStagePreview` and the MCP tools), and the MCP
  `mongo_aggregate`/`mongo_aggregate_preview` handlers additionally apply the production-aware
  `checkWriteAccess` guard used by the write tools.
- **C3. ✅ RESOLVED (2026-07-12).** _TreeView pending edits were keyed by row index and survived
  pagination/tab-switch_ → Save `$set` the wrong document. Now keyed by the document's `_id`
  (`docKey`), resolved back to the doc by `_id` against the current results at save time (skips any
  no longer loaded), and pending edits are cleared whenever `tab.id`/`tab.results` changes.
- **C4. ✅ RESOLVED (2026-07-12).** _Grid inline edit flattened BSON types_ (Date→string,
  ObjectId→string, Decimal128→string, empty cell→`0`). On cell-edit the grid now fetches the
  document's typed shell source, reads the field's original BSON marker, and re-wraps the new value
  in the matching `{$date}`/`{$oid}`/`{$numberDecimal}`/`{$numberLong}`/`{$uuid}` marker (empty
  clears typed/numeric fields to null, not `0`); the row then refreshes to the canonical stored
  value. Falls back to the lossy value only if the typed source can't be fetched (logged).
  _(TreeView nested-field typed editing — M2 — still uses the heuristic parser.)_
- **C5. ✅ RESOLVED (2026-07-12).** _Invalid aggregation JSON threw in render → app-wide white
  screen._ The `buildPipeline(stages)` call feeding `CodeGenModal` is now wrapped in a try/catch, and
  a top-level `ErrorBoundary` (`components/ErrorBoundary.tsx`, wired in `main.tsx`) now catches any
  render-time throw and offers recovery instead of blanking the app.

## 2. High

- SSH tunnel does no host-key verification → MITM. `sshTunnel.ts:78` — add `hostVerifier`.
- Claude agent auto-runs `delete_many`/`update_many` unconfirmed with a "just do it" system prompt,
  while document/profiler/repo text flows back as an unmediated prompt-injection channel.
  `claude.ts:105,268`. Require confirmation for mass mutations; treat tool results as untrusted.
- **H1. ✅ RESOLVED (2026-07-12).** _`matchedCount` never checked_ — a failed match rendered as a
  successful edit until refresh. The grid inline edit, DocumentEditor save, and TreeView save now
  check `matchedCount === 0` and surface an error + refresh instead of showing a false success.
- **H5. ✅ RESOLVED (2026-07-12).** _Filters were never revived_ — `reviveExtended` ran on the
  update body but not the filter, so `{$date}`/`{$oid}` from dialogs and QueryBuilder date rows
  matched nothing. Now `query.ts`/`mutation.ts` run a `reviveFilter` (revive markers → coerce bare
  hex) on every find/count/distinct/explain/update/delete filter, and `convertObjectIds` skips real
  BSON instances so revived types aren't rebuilt into plain objects. QueryBuilder now emits a
  `{$date}` marker for Date rows (`QueryBuilder.tsx`).
- **H2. ✅ RESOLVED (2026-07-12).** _DocumentEditor couldn't `$unset` removed fields (they
  resurrected) and rewrote BSON regex fields as plain strings._ Save now diffs the original top-level
  keys and `$unset`s removed ones; `printShell` renders `RegExp("pat","flags")` and
  `parseShellDocument` parses it back to a `$regex` marker, so regex fields round-trip losslessly.
- **H6. ✅ RESOLVED (2026-07-12).** _DocumentEditor's plain-JSON fallback silently degraded the whole
  document._ The editor now tracks whether the typed shell source loaded; if it didn't, Save warns
  before writing (which would otherwise flatten dates/ObjectIds to strings).
- **H3. ✅ RESOLVED (2026-07-12).** _BulkToolbar "Export" bypassed the lossless exporter_
  (`JSON.stringify` of lossy store docs). It now routes through `exportImport.exportCollection`
  (`serializeToEJSON`, native save dialog) with a `{_id: {$in: ids}}` filter, so exports round-trip.
- **H4. ✅ RESOLVED (2026-07-12).** _Single-collection JSON import stripped `_id`_, regenerating
  every ObjectId and severing references. Import now preserves `_id` (revived via `reviveExtended`),
  matching the DB-level streaming worker. `exportImport.ts`.
- Closing the Claude panel mid-stream strands the tab (`isStreaming` stuck true, text lost) —
  listeners torn down on unmount. `ClaudePanel.tsx:166`, `AppShell.tsx:85` — register once in `App.tsx`.
- Rules-of-Hooks violation — `useState` after early `return null`. `DocumentTable.tsx:225 vs 353`.
- Re-render storm from no-selector store subscriptions across ~10 components (`DocumentTable.tsx:155`,
  TabBar, ClaudePanel, Sidebar, TopBar, …) — select actions individually.
- Stale-response race in `executeQuery` — rapid pagination resolves out of order. `tabStore.ts:312`
  — add a per-tab request token.
- `getRowId` uses nonexistent `params.rowIndex` / stringifies object `_id`s. `DocumentTable.tsx:553`.

## 3. Medium

Security: CSP allows `'unsafe-inline'` + jsdelivr CDN scripts (`index.ts:156`); `window.open`
handler `shell.openExternal`s any scheme with no allowlist (`index.ts:97`); secrets fall back to
plaintext on disk when safeStorage is unavailable, no warning (`config.ts:58`); preload exposes the
generic `ipcRenderer` (`preload/index.ts:8`); `$where`/`$function` pass through filters unfiltered;
`aggregate` buffers the full result set before slicing → OOM risk (`query.ts:115`).

Correctness: every "Run" fires the query twice (`QueryBuilder.tsx:282` + `setPage`); `valueSetter`
mutates store docs in place (`DocumentTable.tsx:281`); `selectedDocIds` never cleared on page/filter
change → bulk-delete off-screen rows (`tabStore.ts:286`); aggregation-tab `DocumentTable` miswired
(dead view buttons; Refresh runs a `find`) (`MainPanel.tsx:205`); `convertObjectIds` coerces any
24-hex string to ObjectId (`mutation.ts:6`, `query.ts:31`); `removeAllListeners` nukes other
subscribers (`ClaudePanel.tsx:175`, `Sidebar.tsx:94`); `reviveExtended` fires on legit
marker-shaped data (`serialize.ts:155`); numeric `5.0`→int32 flips under `$jsonSchema` validators.

## 4. Low

### Post-review hardening (Codex PARTIAL review, 2026-07-12)

A scoped Codex review of the fix series raised 7 issues; all addressed:
- **C4 fetch-failure was still lossy** — the grid inline edit now ABORTS (alert + revert) instead of
  writing the display value when the typed source can't be fetched, and `coerceEditToOriginalType`
  REJECTS invalid ObjectId/date/decimal/integer/boolean input (and Binary/Timestamp) rather than
  downgrading the field to a string.
- **H6 false-safe** — `sourceLoaded` is now set only when the typed shell source is actually
  installed (not when the user edited before it resolved), and the fetch effect keys on
  `tab.id`/`connectionId` too.
- **Filter coercion missed nested arrays** — `convertObjectIds` now recurses into objects inside
  arrays, so hex `_id`s inside `{$and:[…]}`/`{$or:[…]}` (QueryBuilder multi-row) coerce correctly
  (query/mutation/export).
- **Export not revived / not connection-scoped** — `exportCollection` now runs `reviveFilter` (so a
  Date filter exports the rows it counts) and accepts `connectionId` (threaded from BulkToolbar and
  the export dialog).
- **C1 gap in value search** — `valueSearch` is now connection-scoped end to end (router → action →
  dialog).
